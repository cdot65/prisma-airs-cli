# Application-scoped scanner contract (8.1 phase A0)

Status: implementation contract, prepared 2026-11-04 after Claude Code accepted
RUNTIME_HISTORY_IMPLEMENTATION_PLAN.md revision 3 at 9/10. CLI integration is
phase A1; this document does not claim that the new commands already exist.
DESIGN and COMPATIBILITY gain their binding behavior rows with that integration.

## 1. Identity evidence and its limits

| Pinned scm-sdk 0.2.4 field or method | Established meaning | Routing consequence |
| --- | --- | --- |
| ApiKey.api_key_id | Required management key identifier | Public reference only when explicitly supplied by management evidence; never derive it from a secret. |
| ApiKey.customer_app_id | Optional customer_appId field | A missing association is unknown. cust_app/display names are not substitutes. |
| CustomerAppWithKeys.customer_app_id | Required registered-app identifier | Keep in its management namespace; equal display names do not establish a dashboard bucket. |
| CustomerAppWithKeys.api_keys_dp_info | Optional names/deployment-profile/auth-code metadata | No typed key-ID relation is present here. Never match by auth_code or api_key_last8. |
| DashboardSessionOverviewItem.application_id/application_name | Exact dashboard query bucket | Preserve both fields in event identity and session queries. |
| ScanResponse / ScanIdResult | Scan/report/session metadata without a typed dashboard application identity | Preserve request context separately. Never synthesize an app field in the response. |
| Scanner.query_by_scan_ids | One to five UUIDs, no application argument | Choose a credential before the request; no cross-app batches. |
| Scanner.query_by_report_ids | One to five existing opaque report IDs, no application argument | Same routing requirement; keep global ten-ID/two-send limits. |
| Authentication::Scan | With two flat secrets configured, sends Bearer and x-pan-token headers | No server precedence is established. New named sets contain exactly one secret. |

No pinned field establishes universal equivalence between customer_appId and
dashboard application_id. A configured applicationId is an operator's explicit
assertion that this credential may collect that exact dashboard application ID.
The CLI does not claim to have independently verified ownership. It neither
discovers credentials from names nor probes different keys against a scan.
Management credential metadata may support an association, but missing/ambiguous
fields do not authorize a fallback. Application display-name buckets remain
distinct even when one configured applicationId includes multiple exact names.

The official app-scoping statement does not prove original-secret requirements
after rotation. Controlled service qualification is user-run. Tests establish
pinned SDK shapes and local routing policy, not production ownership semantics.

## 2. Named configuration schema

Keep all credentials in the existing D/tenants/NAME.toml, under the same TSG pin,
private-file checks and Transaction lock. The existing 27 scalar keys retain
their types, order, defaults and canonical bytes when the new namespace is absent.
Add one optional structured namespace, scanners. Do not add a configuration
sidecar or read credentials/endpoints from environment variables.

```toml
# Synthetic example; no real credentials.
[scanners]

[scanners.monitor]
applicationId = "app-a"
endpoint = "https://service.api.aisecurity.paloaltonetworks.com"
numRetries = 0
revision = "00000000-0000-4000-8000-000000000001"
apiKey = "FAKE-EXAMPLE-KEY"
```

- scanners must be a table, including when empty. At most 100 entries.
- Names follow the existing tenant-name syntax (1–64 ASCII letters/digits/_/-;
  start alphanumeric), compared with exact case. Reject names equal ignoring
  ASCII case to avoid selecting a different credential by spelling convention.
- Each entry is a strict table with exactly applicationId, endpoint, numRetries,
  revision and one of apiKey/apiToken. Unknown fields, both/neither secret types,
  wrong types or duplicate application IDs invalidate the namespace.
- applicationId is opaque, nonblank under JS trim, at most 4096 bytes and without
  controls. Preserve exact bytes; do not trim or equate names/IDs.
- endpoint is a nonblank URL at most 4096 bytes that passes D48's write rule:
  HTTPS, or HTTP loopback only; no credentials, queries or fragments. It belongs
  to this scanner set and never inherits a management endpoint.
  Store/compare its admitted URL using the existing SDK initialization's URL
  canonicalization and trailing-slash removal. Readers do not rewrite the file.
- numRetries is integer 0–5. CLI inputs default it to 0 and materialize it.
  Bounded result/report reads override retries to zero regardless of this value.
- revision is a canonical lowercase hyphenated UUID generated by each explicit
  set/bind operation, independent of secret bytes. It is a reference, not a hash
  or proof of remote key identity.
- The chosen secret is nonempty printable ASCII without spaces, at most 2048
  bytes, preserving the existing CLI compatibility limit within the SDK's wider
  header bounds (the SDK itself permits up to 16 KiB). Named values are not trimmed.
- The complete tenant file remains bounded to 1 MiB. Parse errors print fixed
  field/namespace reasons, never the parser's input-containing error text.

Canonical writing appends a blank line and [scanners] after scalar lines, then
entries in byte order with the entry fields in the order above (apiToken takes
apiKey's position). Once the namespace exists, preserve an empty [scanners]
marker after the final explicit removal; restoring old format is explicit.

All secrets in every entry join SecretSet before output or client construction.
Raw secret models have no user-facing Serialize/Debug path. Public scanner views
contain name, applicationId, admitted endpoint, numRetries, revision and boolean
hasApiKey/hasApiToken only. No key fragments, auth codes or secret-derived hashes.

tenant read keeps its JSON array of {key,value} rows and appends a scanners row
when the namespace exists. Its value is the public metadata map. tenant get
NAME scanners returns that same public map (empty when absent). Generic tenant
set/unset scanners refuses and points to the dedicated group. Other scalar
set/unset operations preserve the namespace. doctor validates it, exposes only
public metadata, and explains that a bound copy does not follow flat rotation.
No reader creates, locks, changes permissions or rewrites config files.
For named-only tenants, doctor reports named scanner credentials as configured
and skips its default Scanner API probe with an explicit selector-required note.
It never chooses the first named set or probes all configured credentials. Existing
flat-credential probes and management/scanner readiness distinctions remain intact.

## 3. Local management command grammar

```text
airs tenant scanners list TENANT
airs tenant scanners set TENANT NAME (--file PATH | --stdin) [--replace]
airs tenant scanners bind-default TENANT NAME --app-id ID [--use key|token] [--replace]
airs tenant scanners remove TENANT NAME --force
airs tenant scanners snapshots TENANT
airs tenant scanners restore TENANT --file PATH --expect-tsg ID --force
airs tenant scanners delete-snapshot TENANT --file PATH --force
```

The group without a leaf prints help. Scalar options reject repetition. list and
snapshots support pretty/table/json and produce data on stdout. Mutations produce
safe status on stderr and leave stdout empty. --quiet suppresses status, not errors
or durability warnings. All commands are local and build no API client.

set takes a private owner-controlled regular file (0600 or stricter; no symlink)
or bounded piped stdin. Input is strict TOML with applicationId, endpoint, optional
numRetries (default 0) and exactly apiKey or apiToken. revision/scanners wrappers
and unknown input keys are refused. At most 1 MiB; fixed sanitized errors. Do not
accept secrets as argv values. Validate name/flag/input shape before store access;
never hold a lock while consuming input. Register input secrets before reporting
any later configuration/transaction failure.

set and bind-default refuse an existing name unless --replace is explicit.
They also refuse an applicationId bound to a different entry. Rotation replaces
the selected set and generates a new revision; explicit association/endpoint
changes are permitted configuration operations, but cannot silently retarget an
existing polling job. Removing a binding leaves archived history intact.

bind-default uses only the selected tenant's flat credentials. Exactly one
configured kind is selected automatically. With both configured, --use key|token
is required; it never guesses server precedence. A missing selected kind fails
without writes. Preserve flat fields. Materialize the flat scanner endpoint
(including its existing SDK default) and numRetries (configured airsNumRetries,
otherwise the pinned SDK default 5); validate/normalize
the copied header using the existing legacy scanner validation before mutation.
--app-id occurs exactly once and is the explicit dashboard association.

No destructive leaf prompts implicitly: --force is required for remove/restore/
delete-snapshot; omissions are usage errors before tenant access. Explicit file
input plus set/bind is the opt-in configuration-format upgrade; its help and
stderr diagnostic explain older-binary refusal and rollback, without adding an
automatic upgrade on ordinary reads.

## 4. Format rollback snapshots and transaction ordering

Before the first successful named-namespace write, create an exact-byte snapshot
of the previous valid flat-only tenant TOML as
D/tenants/.TENANT.pre-scanners.UUID.toml. It is a private backup, not a registered
tenant or a configuration source. Existing names are never overwritten. Acquire
the existing config.lock, reread/revalidate registration, TSG pin and source
identity, then publish the snapshot privately with no-replace and fsync. Require
snapshot durability before replacing the live config. Refuse unsupported
no-replace filesystems; a snapshot creation/fsync failure leaves live bytes
unchanged. Extend Transaction with a safe no-clobber write primitive if needed;
do not bypass it. Snapshot and config creation roll back together on ordinary
failure; after a crash a harmless orphan snapshot may remain. Never remove a
preexisting or raced snapshot during rollback.

Subsequent named changes use the existing config transaction without making
unbounded new snapshots. Snapshot listing reads only validated filename/metadata,
never secret content. Refuse symlinks/foreign/loose files; do not attach snapshots
to logs, archives or diagnostic reports. No automatic expiry or deletion.

restore accepts only a private snapshot inside that selected store's tenants
directory with the matching tenant prefix, exact registered --expect-tsg pin and
valid TOML under the current reader. A pre-scanners snapshot restores flat format;
a pre-restore snapshot may restore named format and still requires a new binary.
Under the same lock, reread and check both identities before writing original
bytes through Transaction. Before replacement retain the current valid config
as a private no-clobber .TENANT.pre-restore.UUID.toml snapshot,
with the same durability prerequisite, so rollback does not discard newer changes.
No network calls. Failed preflight or transaction leaves live config intact.
delete-snapshot checks selected store/prefix/identity and --force before removing
only that exact private file through Transaction; never accept arbitrary paths.

8.0 and earlier RC binaries intentionally refuse named tables. Test their refusal
using a frozen pre-change CLI against isolated fixture stores. Keep old-version
testing in separate AIRS_CLI_CONFIG_DIR roots; do not silently strip new settings.

## 5. Credential resolution and polling state

- scan/bulk-scan/results/reports accept --scanner NAME. Validate selector syntax
  before tenant access. With no selector use the legacy flat credential plane;
  if absent, require an explicit selector. Never choose the first named entry.
- Management-discovered report/query events use the exact applicationId mapping;
  missing/invalid/ambiguous routing retains management observations and marks
  scanner detail unavailable with the binding remedy. Never fall back to flat.
- Build the scanner only for its configured endpoint and exactly one selected
  secret. Management OAuth and unrelated scanner credentials never enter its
  request. Global transport counters remain shared across all clients.
- Group results by associated application and credential reference; batch at
  five UUIDs. Apply one overall report selection and two-send budget; no fresh
  budget per application. Stop all later report sends after any 429. Return
  honest deferrals when distinct credential groups consume that small allowance.
- Poll legacy bulk state version 1 with flat credentials under the original
  endpoint/tenant checks. Continue writing version 1 for flat-originated jobs.
- Named submissions write state version 2, with scannerReference containing
  name, revision, applicationId and endpoint. Preserve all existing exactly-once
  submission, output identity, private-state and recovery rules.
- resume-poll resolves the saved name automatically. No selector override is
  offered in 8.1. Missing set, changed applicationId or changed endpoint refuses
  before network work. A changed revision at the same app/endpoint is an explicit
  rotation: warn about unqualified historical access and use that one currently
  configured secret. Never try the old or another secret. Persist the reference
  actually used on the next checkpoint without resubmitting accepted work.
- Old binaries reject version 2 as newer, rather than silently using flat keys.
  Version 1 cannot contain scannerReference; version 2 requires a valid one.
  Malformed reference/type/version combinations are refused safely.
- An authorization rejection leaves resumable work pending and exits operationally
  under existing poll semantics; it never becomes allow or causes a new scan.
  Durable deferred/credential-ineligible retry states belong to 8.2's history
  scheduler; do not retrofit SQLite into the 8.1 bulk state engine.

## 6. Phase A0 executable evidence and phase A1 gate

Fixed new error vocabulary (all text still passes the invocation's secret and
terminal filters; existing legacy error strings remain when their cases apply):

| Case | Exit | Message |
| --- | --- | --- |
| Invalid scanner selector/name syntax | 2, before tenant access | Scanner name must be 1–64 letters, digits, hyphens or underscores and start with a letter/digit |
| Invalid credential input TOML/schema/value | 2, before tenant access | Invalid scanner credential input |
| Unsafe/missing/unreadable credential input file | 1, before tenant access | Cannot read private scanner input |
| Existing name without --replace | 1, no mutation | Scanner name already exists; use --replace |
| Duplicate application binding | 1, no mutation | Application ID is already bound to another scanner |
| bind-default with both kinds and no --use | 1, no mutation | Both flat scanner credentials are configured; select --use key or --use token |
| Explicitly selected flat kind absent | 1, no mutation | Selected flat scanner credential is not configured |
| bind-default with neither flat kind | 1, no mutation | Flat scanner credentials are not configured |
| Unknown named selector | 1, no API request | Selected scanner is not configured |
| Named-only direct operation without selector | 1, no API request | No flat scanner credential is configured; select a named scanner with --scanner <name> |
| Named polling reference removed | 1, no API request | Saved scanner is not configured; restore the original binding before resuming |
| Named polling application/endpoint changed | 1, no API request | Saved scanner association or endpoint changed; restore the original binding before resuming |
| Generic set/unset of the structured key | 2, before tenant access | Use 'airs tenant scanners' to change named scanner settings |

Clap's existing usage-error format applies to missing/conflicting/repeated flags;
do not replace it with input-echoing custom parser messages. Snapshot validation,
store failures and durability failures reuse existing sanitized store messages;
new snapshot-only failure is `Cannot safely save scanner rollback snapshot; tenant
configuration was not changed` (exit 1). Snapshot identity/location/pin refusal is
`Scanner snapshot does not match the selected tenant` (exit 1, no mutation).
Incomplete discovery notes give the bind-default/set command grammar with literal
placeholders, never a list of attempted credentials. A changed poll revision emits
one safe warning: `Scanner credentials changed since submission; historical lookup
access is unqualified`. Quiet does not suppress this warning.

Extend tests/signal_sdk.rs with synthetic typed-model checks for optional versus
required app association, absent application identity in scanner results,
non-equivalence of app/name namespaces, and the actual legacy dual-header wire
behavior. These are compatibility checks, not production join qualification.
