# 8.1.0-rc.4 — Application-bound scanner evidence

Unpublished validation candidate for 8.1.0. Signing and publishing workflows are
unchanged; these development artifacts do not publish crates, npm packages or tags.

- Named scanner credentials stay in the tenant TOML store. Bind an existing flat
  key explicitly to a dashboard application ID, or supply private TOML input.
  Direct scans, bulk scans and result/report lookups accept `--scanner NAME`.
- Report/discovery enrichment uses only the application-bound credential. Unbound
  applications retain management observations and an explicit coverage gap. The
  CLI never tries alternate credentials to find a working key.
- Positive management action breakdowns support detector observations even when
  scanner results are unavailable. Scanner classification and enforcement stay
  unknown when they are not supplied. Overview evidence remains session-level.
- Positive sessions receive priority with fair app scheduling. Diagnostics separate
  requested IDs, returned/pending/rejected/missing data, empty and failed reads,
  and actual sends for each application.
- The summary shows reported session totals and violations separately from scans
  and findings, preserving population/window/scale uncertainty. Contradictory
  totals are withheld. Raw detector provenance is retained without double counting.
- Report examples remain supplemental: five IDs by default, ten maximum, at most
  two serial transport sends globally, no retries, immediate stop on HTTP429.

The first named-scanner write is an explicit configuration-format upgrade. It
creates a private exact-byte rollback snapshot before changing the tenant file.
Older binaries refuse named tables. `tenant scanners snapshots/restore` provide
an explicit downgrade path; preserve isolated config roots when testing old builds.
Named bulk jobs use state version2 and refuse removed or retargeted bindings on
resume. Same-app/endpoint rotations use the current credential with an explicit
historical-access warning and never resubmit accepted scans.

Application binding is an operator assertion. Synthetic tests establish routing,
not remote ownership or original-key versus post-rotation permissions. Follow the
budgeted user-run qualification recipe in SIGNAL_BRIEF_TEST_BUILDS.md.

Persistent SQLite history, resumable sync and historical interactive reporting are
planned for the separate 8.2 track; they are not included in this candidate.
