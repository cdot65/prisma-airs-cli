# 9.1.0 — Safer AI Gateway changes

The five versioned workspace crates move together to 9.1.0. Publication status
is established by the corresponding Forgejo release and registry records.

## Preview gateway changes

`gateway deployments update` and `gateway api-keys service create` now support
`--dry-run`. They validate the effective request and selected-tenant binding,
then print a redacted local preview without authentication or service requests.
Preview also skips confirmation prompts and credential-file reservation.

```sh
airs --tenant example gateway deployments update <id> --set auth_settings.allow_all_workspaces=true --dry-run --output json
airs --tenant example gateway api-keys service create --name ci --workspace <uuid> --scopes completions.write --type <credential-type> --dry-run --output json
```

Exit 0 means local preparation succeeded. Inspect `execution_requirements` before
executing: a preview does not establish authorization or service acceptance, and
service-key execution still requires a new private `--secret-output` destination.
The preview is descriptive output, not an executable request file.

## Validation and troubleshooting

- Execution and preview share pure request preparation, including selected-tenant
  binding. Existing identity-pin checks remain enforced.
- With `--debug`, typed-schema and tenant-binding refusals after log creation
  produce a body-free lifecycle event indicating the mutation was not sent.
  Registered-secret filtering applies to every fallback; if no safe record can
  be written, it is suppressed. Parser/configuration/credential and other early
  refusals retain their existing stderr paths.
- Service-key help explains how to supply the required credential type through
  flags, a JSON file, or `--set`. A nonempty locally valid type does not establish
  the service's accepted vocabulary.
- The gateway guide and generated command reference document previews,
  deployment read/write differences, redaction, and installation troubleshooting.

## SDK dependency

The CLI adopts the separately published `scm-sdk` **0.2.6** release, with an exact
registry pin. The SDK adds optional value-free structured validation diagnostics
and preserves diagnostic stages through buffered response decoding. The upgrade
also includes the SDK's MCP tag support introduced in 0.2.5. This CLI
release retains its existing stderr schema messages; field-level presentation
through the shared CLI error bridge remains separate work.

## Remaining limitations

The original organisation-info response mismatch, service-key creation vocabulary
and deployment replacement/merge semantics still need service evidence. Local
validation and synthetic tests do not resolve those contracts.

The optional runtime MCP service is not deployed by this source release; its
Linux storage qualification remains separate. Existing service deployments,
Desktop inputs and distribution-channel installations retain their own artifact
bindings and upgrade procedures.
