# 8.2.0 — Signal Brief, application-bound scanners and the optional MCP service client

8.2.0 is the first stable release since 8.0.0. It carries the 8.1 work, which shipped only as
release candidates, and the CLI side of the optional runtime MCP service.

## Runtime reports and scanners (the 8.1 work)

- **AIRS Signal Brief** is the default `runtime report`: scoped rolling evidence, private
  bundles, and `runtime report --from-evidence` to render saved evidence offline (D337, D340).
- **Scan-log discovery and lookups** — bounded discovery and validation, and scanner-only
  `runtime scan-logs results|reports` lookups (at most 10 report IDs, two sends) (D338, D339).
- **Application-bound scanner credentials** — `airs tenant scanners`, named private TOML sets
  and `--scanner NAME` on direct scans, bulk scans and lookups. The CLI never tries another
  credential to find one that works. The first named-scanner write upgrades the tenant file
  format with a private rollback snapshot; older binaries refuse named tables (D342, D343).
- Management detector evidence, fair priority for positive sessions, and per-application
  report diagnostics (D344). Offline attributed review import (D341).

## The optional runtime MCP service — CLI client

Persistent history now lives in `airs-mcp`, a separately deployed service; the CLI keeps no
history and contains no SQLite. Nothing changes for anyone who does not configure a
connection: without `--mcp` the CLI behaves as before and never falls back silently.

- `airs mcp connections set|list|remove`, `airs mcp login|logout|status` (PKCE through the
  gateway, private session cache) and `airs mcp confirm` (D350, D351, D357).
- With `--mcp CONNECTION`: `runtime history status|coverage|query|reports|download`, lifecycle
  and transfer commands, `runtime jobs`, `runtime schedules`, `runtime sync`,
  `runtime report --mcp` (rendered by the service from its archive, no AIRS calls) and
  `runtime receipts upload` (D352, D355, D356, D358, D359).
- `--record-history CONNECTION` on `runtime scan|bulk-scan|resume-poll` (D360).
- Durable operation receipts and one bounded authentication recovery per submission, so a
  lost response never re-sends work (D354, D361). Service commands without `--mcp` are a usage
  error that names the optional service (D353).
- The earlier local-history commands of the 8.1 candidates were retired: the CLI has no
  archive (D345–D349).

## Packaging

Two library crates are published with the CLI at the same exact version: `airs-runtime-core`
(shared evidence, privacy and rendering) and `airs-mcp-client`. The server (`airs-mcp`) and its
history store are not published; the service ships as a container image. macOS builds of the
whole workspace now compile (a history-store type mismatch on macOS was fixed).
