# airs-cli 8.1.0-rc.1 — AIRS Signal Brief validation candidate

This unpublished release candidate targets stable **8.1.0** after real-tenant
validation. It follows published 8.0.0. The crate, executable and test archives use
8.1.0-rc.1 consistently. No registry publication or release tag has been performed.

## Runtime reporting

- `airs runtime report` now produces the standalone AIRS Signal Brief, replacing
  the previous aggregate HTML layout. It includes grouped detector findings,
  independent scan enforcement actions, current profile comparisons, coverage and
  provenance. Default window is rolling 24 hours; hours/days and repeatable app-ID
  filters are supported.
- Collection uses bounded SDK reads and deterministic detail sampling. Detector
  verdicts remain distinct from allow/block enforcement. Malicious + allow can
  represent intentional monitoring; no confirmed attack, false positive or automatic
  configuration error is inferred.
- Violation excerpts are masked and bounded. DLP matched values are withheld across
  snippets and metadata. Stored full prompts/responses are not fetched automatically.
  Privacy projection refuses ambiguous identity collisions instead of merging scan
  counts, application buckets or profile associations.
- `--bundle-dir` atomically publishes a new 0700 directory containing report.html,
  masked evidence.json and review.md; files are 0600 and destinations are never
  overwritten. `--strict` exits 1 after saving if required collection is incomplete.

## Scan investigation and offline review

- `runtime scan-logs query` now uses dashboard/session discovery and scan-result
  enrichment instead of the broken legacy route. Coverage and unresolved records
  are explicit; deprecated page flags and invalid option combinations are refused.
- `runtime scan-logs results --scan-id` and `reports --report-id` expose existing
  scanner SDK reads, using scanner credentials without management OAuth.
- `runtime report --from-evidence` verifies saved evidence and renders without
  tenant lookup or network clients. Original evidence and its digest are immutable.
- `--review-file` imports the collection-bound Markdown packet. Agent assessments
  and human reviews remain separate, self-attributed annotations. Imported text is
  untrusted data; prompts, templates and code are never executed by the CLI.

## Compatibility and validation

Observable differences from the frozen TypeScript reference are D337–D341 in
DESIGN/COMPATIBILITY. Default report HTML is intentionally different; machine
consumers should use versioned evidence JSON instead of scraping HTML. Evidence,
analysis and redaction versions remain 1; the pinned SDK remains scm-sdk =0.2.4.
Older saved fixtures retain their original producing CLI version during replay.

The implementation passed independent review at 9/10 for every phase and 3,674
workspace tests before this version-only release preparation. Release-candidate
checks and native package smoke results are recorded in SIGNAL_BRIEF_VALIDATION.md
and SIGNAL_BRIEF_TEST_BUILDS.md.

Daily token-detail telemetry has no exact supported SDK window; 24-hour reports
show that supplemental gap. Detail sampling is coverage-oriented, not a population
estimate. Current profile inventory does not establish event-time policy. Real
service qualification remains user-run. These test binaries are unpublished;
macOS development builds are ad hoc signed and not notarized. Production Developer
ID signing, notarization and registry publication remain separate release steps.
