# airs-cli 8.1.0-rc.3 — security profile enablement matrix

This unpublished candidate changes profile presentation following RC2 review.
Profiles appear on the vertical axis, detection services on the horizontal axis,
and check marks identify explicitly enabled services. Known service aliases share
columns. A check means enabled in at least one direction or shared section;
allow/block enforcement and coverage in every direction remain separate.

Blank cells do not establish enablement. Inactive and unknown states retain
accessible labels. Direction, raw service name, action, confidence and location
remain in expandable configuration details. The matrix scrolls horizontally with
sticky profile names, fits printed page width and escapes all dynamic text.
Display omissions are disclosed; full collected configuration remains in evidence.

Collection, scan-result handling, report example limits and strict semantics are
unchanged from RC2. Examples still default to five distinct reports, hard maximum
ten IDs/two serial requests; no retries and stop on 429. No new live collection was
performed. The saved RC2 bundle can be rendered offline with the matrix without
spending API quota or modifying its evidence.

The user-run RC2 report completed configuration inventory but hit its 40-page
session-detail cap and retained unresolved scan results. This presentation change
does not claim to resolve those coverage gaps. Stable 8.1.0 remains on hold pending
real-service qualification. The pinned SDK remains scm-sdk =0.2.4.

Native Linux and macOS validation builds, source/checksum provenance and testing
instructions are recorded in SIGNAL_BRIEF_TEST_BUILDS.md. No publishing or tags
are part of this candidate preparation.
