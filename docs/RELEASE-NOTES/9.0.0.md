# 9.0.0 — TypeScript compatibility removed

9.0.0 is a breaking release. It removes the code that existed only to move from the TypeScript
CLI (7.x). Anyone already using `airs` with its own tenant store is unaffected.

## Breaking changes

- **`airs tenant import` is removed**, with `--from`, `--from-config`, `--name`, `--replace` and
  `--dry-run`. If you still need to copy a TypeScript tenant registry, run the import with 8.2.0
  first, then upgrade. Otherwise register tenants with `airs tenant create <name>`.
- **`PRISMA_AIRS_TENANTS_PATH` no longer has any effect.** It only located the TypeScript
  registry.
- **Messages no longer mention the TypeScript registry.** With an empty store, the "no tenant
  selected" messages, `tenant list` and `airs doctor` name `airs tenant create` only.
- **Doctor's unknown-key hint is the ordinary one.** A tenant file holding `aiGw*`, `agentGuard*`,
  `typesafe*`, `dataDir` or retired `*TokenEndpoint` keys is still invalid; the hint now says to
  remove them rather than naming the TypeScript renames.
- **A TypeScript bulk-scan state is refused like any other foreign file**, with the ordinary
  message. It was never resumable.

The library crates' public API changes with this: `airs-runtime-core` drops `RENAMES`,
`DROPPED_KEYS` and `is_typescript_name`.

## Also since 8.2.0

- `scripts/release.sh` requires every CI job (`linux`, `musl`, `docs-site`) to have passed on the
  released tree, read by one strict parser. It now needs `python3`. CI's docs-only classifier
  fails safe.

## The runtime MCP service

`airs-mcp` has no behaviour change in this release, and no new image is built for it. Production
continues to run the 8.2.0 image.
