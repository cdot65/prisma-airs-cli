# airs-cli 8.1.0-rc.2 — Signal Brief collection remediation

This unpublished candidate follows RC1 user-run qualification. Stable 8.1.0 stays
on hold pending another real-service validation. No publication or release tag is
part of this preparation; the pinned SDK remains scm-sdk =0.2.4.

- Required profile/application configuration receives protected scheduling before
  session traversal. Session-detail pages actually overlap within the concurrency
  cap. Supplemental application telemetry runs last. Page/time/attempt limits still
  produce honest incomplete traversal rather than a completeness claim.
- Analysis rules v2 build findings from detector-positive metadata and scan
  classifications. Explicit detector aliases align scanner/report names with profile
  controls while retaining raw provenance. Detector-positive event observations,
  distinct events/scans, aggregate metrics and detailed example rows have separate
  units. Scan action remains independent of detector verdict/action.
- Report examples default to five distinct IDs, hard maximum ten, batched at five:
  at most two actual serial Reports API sends per invocation. No retries or waiting
  for Retry-After; HTTP 429 stops example enrichment. Missing examples do not
  independently fail strict metadata completeness. `--max-reports 0` makes zero
  report calls and retains metadata findings. Direct `scan-logs reports` also
  accepts at most ten distinct IDs and obeys the two-attempt/rate-limit bounds.
- Missing scanner results may receive at most ten exact-identity management
  transaction reads within ten percent of collection time. Only typed profile/time
  and explicit positive detector breakdowns are retained. Status and extensions
  never become scan verdict/action or report identity; scanner gaps remain visible.
- Detector controls, flags and example labels retain their exact semantics through
  privacy filtering. A control-character or withholding change cannot manufacture
  a recognized alias or monitoring recommendation: report publication refuses such
  transformations, and direct lookup marks changed detector/direction labels unknown.
- Saved rules-v1 bundles and their review bindings still render offline without
  network access. New collections use evidence schema 1, analysis rules 2, redaction 1.
  Source provenance and original saved-file digests remain immutable.

Validation and independent phase reviews are recorded in SIGNAL_BRIEF_VALIDATION.md
and SIGNAL_BRIEF_PHASE_REVIEWS.md. Development packages are documented in
SIGNAL_BRIEF_TEST_BUILDS.md. macOS packages are ad hoc signed, not notarized.

For the user-run real-service check, use a fresh bundle path:

```sh
./target/release/airs --version
./target/release/airs runtime report --strict --bundle-dir ./signal-brief-rc2-validation
```

Expect version 8.1.0-rc.2, protected configuration reads and at most one default
five-ID report batch. Strict may still exit 1 if traversal or scan results remain
incomplete; the saved evidence explains each gap. A second optional run with
`--max-reports 0` makes no Reports API requests. Report collection never submits
scans, retrieves stored full prompts/responses or changes enforcement.
